# @hris/mobile

Expo (SDK 57, expo-router) app for employees and approvers. Talks to the web app's bearer API at `/api/v1` and imports `@hris/shared` from source.

Tabs: Home, Attendance (clock in/out, DTR, corrections), Leave, Requests (overtime, expenses, COE, loans), More (Payslips, Schedule, Announcements, Surveys, HR Assistant, Approvals for managers/HR/admins, Profile, Sign out).

- COE and loan requests are read-only on mobile (no bearer POST route yet); file them on the web.
- HR Assistant streams `POST /api/v1/assistant` through `expo/fetch`, whose `response.body` is a real stream on iOS/Android. If a runtime has no body stream it reads the whole response and parses the NDJSON lines at the end.

## Run it

```bash
pnpm install                                   # from the repo root
pnpm --filter @hris/web dev                    # API on :3000 (or use the deployed URL)
EXPO_PUBLIC_API_URL=http://192.168.1.20:3000 pnpm dev:mobile
```

Scan the QR code with Expo Go (Android) or the Camera app (iOS).

- `EXPO_PUBLIC_API_URL` defaults to `http://localhost:3000`, which only works in a simulator on the same machine. On a phone, use your computer's LAN IP (phone and computer on the same Wi-Fi) or the Vercel URL, e.g. `https://hris.example.com`.
- You can also put it in `apps/mobile/.env` (`EXPO_PUBLIC_API_URL=...`). Restart `expo start` after changing it.
- Seed login: `admin@hris.local` / `Password123!`.

Typecheck: `pnpm --filter @hris/mobile typecheck`.

## Clock in / out

1. Face ID / fingerprint prompt if the phone has one enrolled (local check only, the server never sees it).
2. POST `/api/v1/attendance/today`. If the attendance policy needs a selfie (`PHOTO_REQUIRED`) the front camera opens and a ~320px JPEG is sent; if it needs location (`LOCATION_REQUIRED`) the app asks for it and retries.
3. If the policy requires a passkey (`PASSKEY_REQUIRED`), mobile can't punch: the app shows the server's message. Use the web app, or turn that policy off, until mobile gets its own verified method.

## Publish

You need an [Expo account](https://expo.dev), an Apple Developer Program membership ($99/year) for iOS and a Google Play Console account ($25 one-time) for Android.

```bash
npm i -g eas-cli
eas login
cd apps/mobile
eas init                                       # links the project, writes expo.extra.eas.projectId into app.json

eas build -p ios --profile production          # signs with your Apple account (EAS manages certs)
eas submit -p ios                              # uploads to App Store Connect / TestFlight

eas build -p android --profile production      # .aab for Play
eas submit -p android                          # needs a Play service-account key the first time
```

- Profiles live in `eas.json`: `development` (dev client, internal), `preview` (internal distribution; Android builds an installable APK) and `production` (store builds, build number auto-incremented by EAS).
- Set `EXPO_PUBLIC_API_URL` under `build.<profile>.env` in `eas.json` (replace `https://hris.example.com`). Use HTTPS: release builds block plain HTTP.
- App id is `com.ugnayo.app` (`app.json`). For a per-company build set `APP_ID` / `APP_NAME` when building, e.g. `APP_ID=com.acme.hr APP_NAME="Acme HR" eas build -p ios --profile production`. Store ids can't change after the first upload.
- Icons and splash come from `assets/` and are generated by `node scripts/icons.mjs` (no dependencies). Replace them with real artwork any time; keep `icon.png` 1024x1024 without transparency.
- Push notifications need a development or production build. They don't work in Expo Go on Android.
- Run all EAS commands from `apps/mobile`; EAS detects the pnpm workspace on its own.

## Push notifications

After sign-in the app asks for notification permission (physical devices only), gets an Expo push token and registers it with `POST /api/v1/devices`; sign-out unregisters it. Tapping a notification opens the matching screen: Leave (`/me/leave`, or `/leave/<id>` for employees), Approvals (`/leave/<id>` and `/requests/...` for approvers; Requests for employees), Attendance (`/attendance...`), a payslip (`/payslips/<id>`), a survey (`/surveys/<id>`), Announcements, Schedule, otherwise Home.

- Needs an EAS project id: `eas init` writes `expo.extra.eas.projectId` into `app.json`. Without it the app skips push with a console warning.
- Remote push does not work in Expo Go on Android (SDK 53+). Use a development build: `eas build -p android --profile development`.
- Users can turn push off on the web under Security > Notifications.
